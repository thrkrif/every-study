# ADR-0003: 모듈러 모놀리스와 패키지 규칙

- 상태: 확정 (2026-11-13)
- 일자: 2026-11-11
- 관련: [ARCHITECTURE 3장](../ARCHITECTURE.md)

## 배경

초기 규모는 소규모(서버 1대)이고 개발 인원도 적다. 반면 도메인에는 서로 얽힌 규칙(정원, 승계, 출석, 점수, 제재)이 많아 경계를 흐리면 금세 엉킨다.

## 결정

- **배포 단위는 하나**(Spring Boot 모놀리스), 내부는 **기능별 모듈**로 나눈다. 모듈 목록은 ARCHITECTURE 3장에 있다.
- 패키지는 **기능 우선**(`<root>.study`, `<root>.attendance` …)이고 그 안에서 `web`, `service`, `domain`, `repository`로 나눈다. 계층 우선(`controller/`, `service/` 최상위)은 쓰지 않는다.
- 다른 모듈의 `domain`·`repository`는 **참조 금지**. 공개 `service` 인터페이스 또는 도메인 이벤트로만 소통한다.
- 모듈 간 비동기 반응은 Spring 이벤트(`AFTER_COMMIT`)로 한다. 이 이벤트는 **같은 프로세스 안에서만** 신뢰한다. 반드시 전달돼야 하는 것(알림)은 아웃박스에 기록한다 (ADR-0005).
- 경계는 **아키텍처 테스트**로 CI에서 검사한다 (도구는 구현 시 확정, ArchUnit 후보).
- 루트 패키지명은 `com.everystudy`다 (임시, 도메인이 정해지면 IDE 리팩터링으로 바꾼다).

## 대안

- **마이크로서비스**: 운영·분산 트랜잭션 비용이 커서 기각. 모듈 경계를 지키면 나중에 분리할 수 있다.
- **계층 우선 단일 패키지**: 시작은 쉽지만 도메인이 커지면 경계가 사라져 기각.

## 결과와 영향

- 모듈 간 호출은 약간 번거롭지만, 이벤트와 인터페이스 덕에 변경 범위가 작다.
- 정합성이 필요한 곳(정원, 승계)은 한 트랜잭션 안에서 처리하고, 이벤트로 흩뿌리지 않는다.
- 규모가 커지면 `chat`, `notification`이 첫 분리 후보다.
