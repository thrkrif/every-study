# 모두의 스터디 — 기능 명세 (MVP)

> 부제(안): 약속 지키는 사람들의 스터디
> 상태: 확정 v0.5 · 수치는 모두 "제안값"이며 운영하며 조정 (설정값으로 분리)
> v0.5 변경: **스터디는 하루 한 번의 모임(세션 1건)으로 확정**. 반복 세션·종료일·종료일 연장 삭제, 신청 마감은 세션의 체크인 오픈까지, 같은 사람과 계속하는 기능(친구 등)은 후속 과제로 기록
> v0.4 변경: 스터디 종료일 필수와 종료 시 채팅방 폐쇄(4.14), 모집 마감 토글 없음·정원 2~6명과 증액·대기(자리 나면 알림), 신청 마감은 다음 세션 체크인 오픈까지, 주최자 강퇴 기능 영구 제외, 신고 조치 범위 확정(4.11), 투표·블랙리스트는 검토 과제로 기록
> v0.3 변경: 참여 신청은 주최자 승인 없이 누구나 자유롭게(입장 기준만 자동 검증), 사전/직전 취소 및 주최자 이탈 기준 2시간→3시간, 승계는 수락/거절 없이 남은 참여자 중 무작위 자동 배정, 위치 거부 시 일회용 코드만 허용, 지도 API 카카오맵, 초기 규모 소규모로 확정
> v0.2 변경: 대면 스터디 전용 MVP(핑·온라인 출석 제외), 주최자 지표 단순화, 채팅방 기반 주최자 승계, 탈퇴·재가입 정책은 운영 후 과제로 이동

## 1. 서비스 개요

- **무엇**: 전 직군 취준생이 동네(구 단위)에서 **대면 스터디**를 만들고 참여하는 매칭 서비스
- **차별점**: 사람이 매기는 평가 없이, **출석 기록만으로 만든 신뢰 지표(출석률)** 로 노쇼·지각을 억제
- **성격**: 친목 도모 서비스가 아니다. 스터디를 약속대로 진행하게 하는 것이 목적이며, 채팅은 스터디 운영용으로 한정되고 스터디 종료와 함께 폐쇄된다 (4.14)
- **형태**: 모바일 웹(반응형) 우선. 백엔드는 Spring Boot REST API, 프론트는 Next.js(React)로 분리 (추후 앱 확장 가능)
- **초기 운영 전략**: 수원시(장안·권선·팔달·영통 4개 구)로 시작해 점차 확장, 직군 제한 없이 시작, 운영자(본인)가 시범 스터디 2~3개 직접 개설
- **확장 계획(MVP 이후)**: 사용자 리뷰를 보고 필요하면 **비대면 스터디**를 별도 종류로 추가(Zoom/Meet 연동). 대면 스터디는 계속 대면으로만 진행

## 2. 용어

| 용어 | 정의 |
|---|---|
| 스터디 | 주최자가 만든 모임 단위. **하루 한 번의 모임**이며 다음 모임은 새 스터디로 만든다 |
| 세션 | 스터디의 일정 (날짜·시간·장소). MVP에서는 스터디 1개에 세션 1건. 출석과 지표는 세션 단위로 기록 |
| 주최자 | 스터디를 만든 사용자 (호스트). 승계되면 새 주최자로 바뀜 |
| 참여자 | 신청이 확정되어 스터디에 속한 사용자 |
| 희망 직군 | 주최자가 "이런 직군과 함께하고 싶다"고 고른 태그. 참여 제한이 아닌 안내용 |
| 출석률 | 최근 N회 세션 기준 출석 비율 (신뢰 지표) |
| 승계 | 주최자가 채팅방을 나갈 때 남은 참여자 중 한 명이 새 주최자가 되는 것 (4.13) |
| 체크인 오픈 | 세션 시작 10분 전. 장소에서 출석 체크인 버튼을 누를 수 있게 되는 시점이며 채팅방과는 무관하다. 채팅방은 스터디 생성 시 함께 만들어진다 (4.6, 4.12) |
| 종료 | 세션 날짜의 다음날 00:00(한국 시간)에 스터디가 끝나는 것 (4.14) |
| 대기 | 정원이 찬 스터디에서 "자리가 나면 알려 달라"고 하는 신청. 참여가 아님 (4.14) |

## 3. 사용자 역할

- **비회원**: 스터디 목록/상세 열람만 가능
- **회원**: 스터디 생성·참여, 출석, 마이페이지
- **주최자**: 자기 스터디 관리 (세션 관리, 입장 기준 설정, 정원 설정·증액). 참여 신청을 승인·거절하지 않고, **참여자를 강퇴할 수 없으며**, 모집 마감을 직접 켜고 끌 수 없음. 출석을 일방적으로 확정할 수도 없음
- **운영자(관리자)**: 이의 신청 처리, 제재 해제, 신고 대응 (간단한 어드민)

## 4. 기능 명세

### 4.1 회원/프로필
- **카카오·구글 소셜 로그인** (확정). 가입 시 닉네임, **내 직군(단일 선택)**, 활동 지역(구 단위) 입력
- **탈퇴 (MVP는 단순하게)**: 탈퇴 즉시 닉네임·이메일·소셜 식별값 등 개인정보 삭제, 다른 사용자의 기록(채팅, 출석 집계)에 남는 흔적은 "탈퇴한 사용자"로 익명 처리
    - 진행 중인 스터디가 있으면 탈퇴 전에 참여 취소(4.4) 또는 주최자 승계(4.13) 규칙이 먼저 적용됨
    - 재가입 방지·이력 보관·SMS 인증은 MVP에 넣지 않음 (**운영 후 과제**, 9장)
- 프로필 공개 정보: 닉네임, 직군, 지역, **출석 지표**(4.7), 가입일
- 비공개: 이메일 등 개인정보

### 4.2 스터디 생성 (주최자)
| 항목 | 설명 |
|---|---|
| 제목 / 소개 | 필수 |
| 주제 | 고정 카테고리 (취업준비, 자격증, 어학, 공무원, 개발, 기타 등) |
| **희망 직군** | 복수 선택, 고정 목록(~15개) + "직군 무관" |
| 진행 방식 | **대면(오프라인) 고정**. 데이터에는 스터디 종류 필드를 두어 이후 비대면 추가 가능하게 함 |
| 지역·장소 | 필수. 구 단위 지역(수원 4개 구) + **상세 장소(지도에서 선택, 좌표 저장)** |
| 정원 | **2~6명** (주최자 포함, 상한은 설정값). 주최자가 정하고 상한까지 늘릴 수 있음 (줄일 때는 현재 참여자 수 미만 불가, 4.14) |
| **일정** | **하루 한 번**. 날짜와 시작 시각을 정한다. 개설 가능 범위는 오늘부터 14일 뒤까지(오늘이 11일이면 25일까지, 제안·설정값). 반복 일정은 없고, 다음에 또 하려면 새 스터디를 만든다. 일정(날짜·시간·장소)은 개설 후 수정할 수 있고 수정하면 참여자에게 즉시 알린다 |
| 진행 시간 | 분 단위로 입력해 종료 시각을 계산 (제안). 화면의 "진행 중/지난 모임" 구분과 알림에만 쓰고 출석 판정에는 쓰지 않음. 시작한 날 안에 끝나야 함 |
| 종료 | 세션 날짜의 다음날 00:00(한국 시간)에 자동 종료. 종료된 스터디는 되살리지 않는다 (4.14) |
| 참여 방식 | 자유 신청 (주최자 승인 없음). 정원 여유와 입장 기준(출석률/신규)을 충족하면 즉시 참여 확정 |
| **입장 기준** | 최소 출석률 N% 이상 / 신규 허용 여부 (4.7 참고) |
| 연락 수단 | 스터디 전용 채팅방 자동 생성 (4.12) |

### 4.3 스터디 탐색
- 목록: 지역, 주제, 희망 직군, 모집 중 여부 필터 / 최신순·마감임박순 정렬
- 카드 표시: 제목, 지역, 날짜·시간, 정원(현재/최대), 희망 직군 태그, **입장 기준 배지**, 주최자 지표
- 상세: 소개, 일정, 참여자 목록(닉네임 + 출석 지표), 참여 신청 버튼 (정원이 찼으면 신청 대신 "대기하기" 버튼, 4.14)

### 4.4 참여 신청
1. 신청 → 검증 통과 시 **즉시 참여 확정** (주최자 승인·대기 없음) → 채팅방 입장
2. **검증 순서**: 스터디 상태(진행 중) → 정원 → 이용 제한 상태 → 입장 기준(출석률/신규) → 중복 신청. 진행 중이고 정원에 여유가 있으면 세션의 체크인 오픈 전까지 신청할 수 있음 (4.14)
3. 내 직군이 희망 직군과 다르면 **안내 문구만 표시**(막지 않음)
4. **정원 동시성**: 마지막 1자리에 동시 신청이 와도 초과 확정 금지 (락/원자 처리)
5. 참여자가 채팅방을 나가면 참여 취소로 처리. 취소 시점에 따라 출석 지표에 영향 (4.6)

### 4.5 세션 & 알림
- 일정 변경·취소(주최자 포기, 파투) 시 참여자에게 즉시 알림
- 일정 알림: **전날**, **1시간 전**, **체크인 오픈 시점**
- 채널: 웹 푸시(PWA) + 이메일 (초기). 알림톡은 사용자 증가 후 검토
- 대기 알림: 대기 중인 스터디에 자리가 생기거나 정원이 늘면 대기한 사람에게 알림 (4.14). 위 웹 푸시·이메일로 보내므로 건별 비용이 드는 알림톡을 쓰지 않는다
- 알림 수신 설정(채널별 on/off)

### 4.6 출석 체크 (핵심)
**원칙: 본인 체크인이 기본. 주최자도 참여자와 동일하게 체크인하며, 주최자가 노쇼를 일방적으로 확정하지 못함**

체크인 방식 (GCOO처럼 위치 기반, 대면 전용)
- 체크인 순간 **참여자 본인 휴대폰 위치**가 **스터디 장소 반경 내**(제안 150m, 실내 GPS 오차 고려)이면 체크인 버튼 활성화. 위치는 체크인 순간에만 사용
- 주최자도 동일하게 체크인
- **주최자 미도착 규칙**: 시작 + 30분까지 주최자 체크인이 없으면 세션을 '무효' 처리 → 참여자는 노쇼 아님, 주최자 불참만 기록 (QR 방식의 "주최자 노쇼 시 전원 노쇼" 문제 해결)
- GPS 실패 대비 보조 수단: 주최자가 보여주는 일회용 코드 입력 (주최자 체크인 완료 시에만 유효). **위치 권한을 거부했거나 GPS가 실패한 경우의 유일한 대체 수단**이며, 코드로 체크인해도 출석·지각 판정은 시각 기준으로 동일하게 적용
- 체크인 가능 시간(설정값): 시작 10분 전 ~ 시작 후 30분
- **신청 마감**: 신청은 세션의 체크인 오픈(시작 10분 전)까지 받는다. 그 이후에는 정원이 남아도 신청할 수 없고 대기도 닫힌다. 따라서 출석 집계 대상은 신청이 확정된 참여자 전원이다 (4.14)
- 세션 중 확인 핑 없음. 출석 여부는 체크인 한 번으로 판정

자동 판정 (제안값)
| 상태 | 조건 |
|---|---|
| 출석 | 시작 시각 + 10분 이내 체크인 |
| 지각 | 시작 + 10분 초과 ~ 30분 이내 체크인 |
| 노쇼 후보 | 주최자는 체크인했으나 해당 참여자는 체크인 없음 → 세션 종료 후 자동 판정 |
| 노쇼 | 통지 후 이의 기간(48시간) 경과, 또는 이의 기각 |
| 세션 무효 | 주최자 미도착. 참여자 지표 영향 없음, 주최자는 -1 (4.13) |
| 사전 취소 | 시작 **3시간 전까지** 참여 취소 — 지표에 영향 없음 |
| 직전 취소 | 시작 **3시간 이내** 참여 취소 — 노쇼보다 가벼운 감점으로 집계 |

- 사전/직전 취소 기준은 주최자와 같은 **3시간**으로 통일 (v0.1의 24시간, v0.2의 2시간에서 변경)
- 주최자의 수동 변경은 전부 로그로 남김

### 4.7 출석 지표 (사람 평가 없음)
- 표시 형태: **"출석률 92% · 최근 10회 중 노쇼 0회 · 지각 1회"**
- 계산 (제안): 최근 10회 세션 기준
  `출석률 = (출석 + 지각) / (출석 + 지각 + 노쇼 + 직전취소)` · 사전 취소는 분모 제외
- 주최자 귀책(세션 무효, 주최자 포기)으로 진행되지 않은 세션은 **모든 참여자의 분모에서 제외**
- **신규 배지**: 집계 대상 세션이 3회 미만이면 숫자 대신 "신규"
- 입장 기준 옵션 (주최자 설정)
    - 최소 출석률 N% (예: 70)
    - 신규 허용 / 신규 불허 (**기본값: 허용**)
- 점수 변동 이력은 이벤트로 저장하고, 사용자 집계값은 캐시 (정책 변경 시 재계산 가능)

### 4.8 참여자 제재 (단계별, 제안값)
| 단계 | 조건 | 효과 |
|---|---|---|
| 경고 | 노쇼 1회 | 안내 알림 |
| 제한 | 최근 5회 중 노쇼 2회 | 7일간 새 스터디 참여 신청 불가 (기존 스터디는 유지) |
| 정지 | 제한 후 재발 / 최근 10회 중 노쇼 4회 | 14일 이용 정지 |

### 4.9 이의 신청
- 대상: 노쇼/지각 판정. 기한 48시간, 사유 텍스트 + (선택) 증빙
- 처리: 1차 주최자 의견 → 운영자 최종 결정. 인정 시 기록 정정 + 지표 재계산
- 악용 방지: 동일 사용자 이의 반복 기각 시 제한

### 4.10 마이페이지
- 내 지표, 참여/주최 중인 스터디, 다가오는 세션, 지난 출석 기록, 알림 설정, 이의 신청 내역

### 4.11 신고/운영
- 스터디·사용자 신고(부적절한 모집 등), 채팅 메시지 신고(4.12), 관리자 목록·처리 화면
- **운영자 조치 (MVP)**
    1. 신고 반려 또는 처리 완료 표시 (사유·시각 기록)
    2. 스터디 숨김(목록에서 제외) 또는 강제 종료. 강제 종료는 파투로 처리하며 참여자 지표에 영향 없음
    3. 신고된 채팅 메시지 삭제
    4. 사용자 이용 정지 부여·해제 (4.8의 자동 제재와 별개의 수동 조치)
- 모든 운영자 조치는 감사 로그에 남긴다

### 4.12 채팅 (MVP 포함)
- 스터디당 채팅방 1개. 스터디 생성 시 주최자와 함께 만들어지고, **참여가 확정된 사람만** 입장·열람 (나가기, 스터디 종료 시 접근 차단. 주최자의 강퇴 기능은 없음)
- 텍스트 메시지 중심, 공지(주최자) 고정, 읽지 않음 표시, 새 메시지 알림
- 메시지 저장(DB) 및 이전 대화 페이징 조회
- 신고·차단(메시지 단위) 최소 기능
- 스터디가 종료되면 채팅방을 폐쇄하고 메시지는 일정 기간 뒤 삭제한다 (4.14). 채팅은 친목용이 아니라 스터디 운영용이다
- **채팅방 나가기의 의미**
    - 참여자가 나가면 → 참여 취소 (4.4, 4.6)
    - 주최자가 나가면 → 주최 포기. **승계 규칙 적용** (4.13)
- 구현 방향: WebSocket(STOMP) + 단일 서버 시작, 서버 증설 시 외부 STOMP 브로커(RabbitMQ 등) 연결을 검토 (Redis pub/sub은 Spring STOMP 릴레이와 바로 연결되지 않음, ADR-0005)

### 4.13 주최자 지표와 승계

**A. 주최자 포기(채팅방 나가기)와 승계**
| 상황 | 처리 |
|---|---|
| 채팅방에 **주최자만** 남음 | 스터디는 **파투(취소)**. 영향받는 참여자가 없으므로 감점 없음 |
| 채팅방에 **참여자가 1명 이상** 남음 | 남은 참여자 중 **무작위 1명**이 새 주최자가 됨 (승계). 장소·일정·입장 기준 등 설정은 그대로 승계 |

- 주최자는 스터디 운영상 역할이 크지 않으므로 **수락/거절 없이 자동 배정**한다 (확정). 새 주최자에게는 알림만 보낸다
- 추첨 대상은 추첨 시점에 채팅방에 남아 있는 참여자로 한정한다. 주최자 나가기와 참여자 나가기가 겹쳐도 대상자는 한 명으로만 정해져야 한다 (8장)
- 배정 후에는 일반 주최자 규칙이 그대로 적용된다 (불참 시 -1 등)
- 승계 기록은 남기되, 새 주최자의 지표에는 승계 자체가 불이익이 되지 않음
- **승계는 세션 시작 전까지만** 한다 (확정). 시작 이후에 주최자가 나가면 승계하지 않는다. 주최자가 이미 체크인했다면 모임과 출석은 그대로 진행되고, 체크인 전이었다면 4.6의 미도착 규칙으로 처리한다

**B. 주최자 감점 (단일 규칙)**
- **세션 시작 3시간 이내**에 주최자가 채팅방을 나가거나, 주최자 미도착으로 세션이 무효가 되면 **-1점** (영향받는 참여자가 있을 때만)
- 그보다 일찍 나가는 경우는 감점 없음 (횟수는 표시)
- 점수는 90일 롤링 후 소멸

**C. 주최자 제재 (90일 내 합계, 제안값 — 기존 3/5/8에서 축소, 확인 필요)**
| 합계 | 효과 |
|---|---|
| 2점 | 경고 |
| 3점 | 새 스터디 개설 7일 제한 |
| 5점 이상 | 새 스터디 개설 30일 제한 + 운영자 검토 |

- 자동 영구정지 없음. 불가항력 면제, 참여자 신고 기반 노쇼 확정은 MVP에서 제외(이의 신청 4.9로 갈음)

**D. 표시와 참여자 보호**
- 표시: "주최 N회 중 직전 이탈 N회". 주최 5회 미만은 퍼센트 대신 건수만 표시
- 주최자 귀책으로 진행되지 않은 세션은 참여자의 출석률 분모에서 제외, 참여자 노쇼·취소 기록 없음, 변경 시 즉시 알림

### 4.14 스터디 상태, 정원, 종료
**상태**
- 저장되는 상태는 **진행 중**(개설 ~ 세션 날짜) / **종료**(세션 날짜 다음날 00:00) / **파투**(4.13A, 운영자 강제 종료 등) 세 가지다.
- "모집 중"과 "마감"은 별도 상태가 아니라 **파생**이다. 진행 중이고 체크인 오픈 전이며 정원에 여유가 있으면 모집 중, 정원이 차거나 체크인이 열리면 마감이다. **주최자가 모집 마감을 직접 켜고 끌 수 없다.**

**신청 가능 시점**
- 정원에 여유가 있으면 세션의 체크인 오픈(시작 10분 전)까지 신청할 수 있다 (4.6). 그 이후에는 신청과 대기가 닫힌다.

**정원과 대기**
- 정원은 **2~6명**이다 (주최자 포함, 상한은 설정값). 주최자는 정원을 정하고 상한까지 늘릴 수 있다. 줄이는 것은 현재 참여자 수까지만 가능하다.
- 정원이 찬 스터디에서는 신청 대신 **대기**할 수 있다. 대기는 참여가 아니라 "자리가 나면 먼저 알려 달라"는 신청이며, 대기자를 자동으로 참여시키지 않는다.
- 자리가 생기거나(참여자가 나감) 정원이 늘면 **대기 중인 사람에게 알림**을 보내고, 참여 신청은 **선착순**이다. 대기하지 않은 사람도 같은 때에 신청할 수 있다 (누구나 참여 가능).
- 주최자는 **대기 인원 수**를 볼 수 있고, 이를 보고 정원을 늘릴지 판단한다. 대기자의 신원은 공개하지 않는다(제안).
- 대기는 언제든 취소할 수 있고, 체크인 오픈 후, 스터디가 종료되거나 파투되면 자동 해제된다.
- 대기자 신청 우선권은 두지 않는다 (먼저 신청한 사람이 자리를 차지). 우선권 도입은 후속 과제다 (9장).
- 알림은 서비스 자체 채널(웹 푸시·이메일, 4.5)로 보내므로 건별 비용이 들지 않는다. iOS는 홈 화면에 추가한 앱에서만 푸시가 동작해 이메일이 보조 수단이 된다.

**종료 처리 (세션 날짜 다음날 00:00, 한국 시간)**
- 스터디 상태를 종료로 바꾸고 **채팅방을 폐쇄**한다 (입장·열람·전송 차단).
- 채팅 메시지는 폐쇄 후 **7일간 보관**(신고 대응용, 설정값)한 뒤 **영구 삭제**한다.
- 출석 기록, 출석 지표, 제재는 그대로 유지한다. 이의 신청(4.9)은 스터디 종료와 무관하게 기한 안에 할 수 있다.
- 서비스의 목적이 친목이 아니므로 종료 후 채팅방을 남기지 않는다.

## 6. 핵심 흐름

**참여**: 목록 → 상세 → 신청 → 참여 확정(즉시) → 채팅방 입장 (정원이 찼으면 대기하기 → 자리 나거나 정원이 늘면 알림 → 선착순 신청)
**종료**: 세션 날짜 경과 → 다음날 00:00 스터디 종료·채팅방 폐쇄 → 7일 후 메시지 삭제 (출석 기록은 유지)
**출석**: 전날/1시간 전 알림 → 체크인 오픈 알림 → 장소 도착 후 체크인 → 출석/지각 자동 기록
**노쇼**: 미체크인 → 노쇼 후보(자동) → 참여자에게 통지(이의 48h) → 확정 → 지표 반영·제재 판정
**이의**: 통지 → 이의 신청 → 주최자 의견 → 운영자 결정 → 지표 재계산
**주최자 포기**: 주최자가 채팅방 나가기 → (참여자 없음) 파투 / (참여자 있음) 남은 참여자 중 무작위 1명이 자동으로 새 주최자 (알림 발송) → (시작 3시간 이내였다면) 전 주최자 -1

## 7. 범위 밖 (MVP 제외)

- 비대면(온라인) 스터디와 Zoom/Meet 연동, 세션 중 확인 핑, 온라인/오프라인 출석률 분리 표시 (이후 사용자 리뷰를 보고 별도 종류로 추가 검토)
- 탈퇴 후 이력 보관·재가입 방지, SMS 인증
- 반복 일정·여러 날에 걸친 스터디 (같은 사람과 계속하려면 새 스터디를 만들거나 서로 연락한다)
- 앱 출시, 추천 알고리즘, 결제/장소 예약, 알림톡
- 사용자 간 평가(영구 제외)
- 주최자의 참여자 강퇴 기능 (MVP 이후에도 만들지 않음. 문제 사용자는 신고와 운영자 제재로 다룸)

## 8. 비기능 요구

- 정원 마감 동시 신청 정합성, 알림 발송 신뢰성(재시도), 점수 변동 감사 로그
- 주최자 승계 시 동시성: 주최자 나가기와 참여자 나가기가 겹쳐도 승계 대상이 한 명으로만 정해져야 함
- 위치 정보는 체크인 순간만 사용·저장 최소화 (개인정보 처리방침 필요)
- 정책 수치(시간창, 임계값, 감점, 채팅 보관 기간)는 설정으로 분리
- 스터디 종료 경계(세션 날짜 다음날 00:00)는 한국 시간 기준으로 정확히 처리해야 함. 종료·삭제 처리는 재실행해도 결과가 같아야 함

## 9. 결정 현황

**확정**: **스터디는 하루 한 번의 모임(세션 1건)**, 세션 날짜 다음날 00:00 종료와 채팅방 폐쇄(메시지 7일 후 삭제), 신청은 체크인 오픈(시작 10분 전)까지, 주최자는 정원을 정하고 늘릴 수 있으나 모집 마감을 켜고 끌 수 없음, 정원은 2~6명이고 정원이 찬 스터디는 대기(자리 나면 알림, 선착순 신청), 주최자 강퇴 기능 영구 제외, 신고 조치 4종(반려·처리 완료, 스터디 숨김·강제 종료, 메시지 삭제, 사용자 이용 정지), 지도·장소 API는 카카오맵, 초기 규모는 소규모(수원 4개 구, 서버 1대), 위치 권한 거부·GPS 실패 시 대체 수단은 일회용 코드만(주최자 체크인 후 유효), 소셜 로그인(카카오·구글), 채팅 MVP 포함, 지역 구 단위, 시작 지역 수원시(4개 구), 위치 기반 체크인(반경 150m, 설정값), 주최자는 언제든 포기 가능하되 세션 시작 3시간 이내 포기만 감점(승계로 배정된 새 주최자도 동일), **대면 스터디 전용 MVP**, 핑 없음, 참여 신청은 주최자 승인 없이 자유 신청, 사전/직전 취소 기준 3시간, 주최자 감점은 3시간 이내 이탈 -1 단일 규칙, 채팅방 나가기 기반 주최자 승계(세션 시작 전까지만, 남은 참여자 중 무작위 자동 배정, 수락/거절 없음), 채팅방은 스터디 단위, 프론트 Next.js
