# 모두의 스터디 — 기능 명세 (MVP)

> 부제(안): 약속 지키는 사람들의 스터디
> 상태: 확정 v0.3 · 수치는 모두 "제안값"이며 운영하며 조정 (설정값으로 분리)
> v0.3 변경: 참여 신청은 주최자 승인 없이 누구나 자유롭게(입장 기준만 자동 검증), 사전/직전 취소 및 주최자 이탈 기준 2시간→3시간, 승계는 수락/거절 없이 남은 참여자 중 무작위 자동 배정, 위치 거부 시 일회용 코드만 허용, 지도 API 카카오맵, 초기 규모 소규모로 확정
> v0.2 변경: 대면 스터디 전용 MVP(핑·온라인 출석 제외), 주최자 지표 단순화, 채팅방 기반 주최자 승계, 탈퇴·재가입 정책은 운영 후 과제로 이동

## 1. 서비스 개요

- **무엇**: 전 직군 취준생이 동네(구 단위)에서 **대면 스터디**를 만들고 참여하는 매칭 서비스
- **차별점**: 사람이 매기는 평가 없이, **출석 기록만으로 만든 신뢰 지표(출석률)** 로 노쇼·지각을 억제
- **형태**: 모바일 웹(반응형) 우선. 백엔드는 Spring Boot REST API, 프론트는 Next.js(React)로 분리 (추후 앱 확장 가능)
- **초기 운영 전략**: 수원시(장안·권선·팔달·영통 4개 구)로 시작해 점차 확장, 직군 제한 없이 시작, 운영자(본인)가 시범 스터디 2~3개 직접 개설
- **확장 계획(MVP 이후)**: 사용자 리뷰를 보고 필요하면 **비대면 스터디**를 별도 종류로 추가(Zoom/Meet 연동). 대면 스터디는 계속 대면으로만 진행

## 2. 용어

| 용어 | 정의 |
|---|---|
| 스터디 | 주최자가 만든 모임 단위. 여러 번의 세션으로 구성 |
| 세션 | 스터디의 개별 일정 (날짜·시간·장소 1건) |
| 주최자 | 스터디를 만든 사용자 (호스트). 승계되면 새 주최자로 바뀜 |
| 참여자 | 신청이 확정되어 스터디에 속한 사용자 |
| 희망 직군 | 주최자가 "이런 직군과 함께하고 싶다"고 고른 태그. 참여 제한이 아닌 안내용 |
| 출석률 | 최근 N회 세션 기준 출석 비율 (신뢰 지표) |
| 승계 | 주최자가 채팅방을 나갈 때 남은 참여자 중 한 명이 새 주최자가 되는 것 (4.13) |

## 3. 사용자 역할

- **비회원**: 스터디 목록/상세 열람만 가능
- **회원**: 스터디 생성·참여, 출석, 마이페이지
- **주최자**: 자기 스터디 관리 (세션 관리, 입장 기준 설정). 참여 신청을 승인·거절하지 않음. 출석을 일방적으로 확정할 수는 없음
- **운영자(관리자)**: 이의 신청 처리, 제재 해제, 신고 대응 (간단한 어드민)

## 4. 기능 명세

### 4.1 회원/프로필
- **카카오·구글 소셜 로그인** (확정). 가입 시 닉네임, **내 직군(단일 선택)**, 활동 지역(구 단위) 입력
- **탈퇴 (MVP는 단순하게)**: 탈퇴 즉시 닉네임·이메일·소셜 식별값 등 개인정보 삭제, 다른 사용자의 기록(채팅, 출석 집계)에 남는 흔적은 "탈퇴한 사용자"로 익명 처리
    - 진행 중인 스터디가 있으면 탈퇴 전에 참여 취소(4.4) 또는 주최자 승계(4.13) 규칙이 먼저 적용됨
    - 재가입 방지·이력 보관·SMS 인증은 MVP에 넣지 않음 (**운영 후 과제**, 9장)
- 프로필 공개 정보: 닉네임, 직군, 지역, **출석 지표**(4.7), 가입일
- 비공개: 이메일 등 개인정보

### 4.2 스터디 생성 (주최자)
| 항목 | 설명 |
|---|---|
| 제목 / 소개 | 필수 |
| 주제 | 고정 카테고리 (취업준비, 자격증, 어학, 공무원, 개발, 기타 등) |
| **희망 직군** | 복수 선택, 고정 목록(~15개) + "직군 무관" |
| 진행 방식 | **대면(오프라인) 고정**. 데이터에는 스터디 종류 필드를 두어 이후 비대면 추가 가능하게 함 |
| 지역·장소 | 필수. 구 단위 지역(수원 4개 구) + **상세 장소(지도에서 선택, 좌표 저장)** |
| 정원 | 2~N명 |
| 일정 | 세션 반복 규칙(주 N회, 요일·시간) 또는 단건 |
| 참여 방식 | 자유 신청 (주최자 승인 없음). 정원 여유와 입장 기준(출석률/신규)을 충족하면 즉시 참여 확정 |
| **입장 기준** | 최소 출석률 N% 이상 / 신규 허용 여부 (4.7 참고) |
| 연락 수단 | 스터디 전용 채팅방 자동 생성 (4.12) |

### 4.3 스터디 탐색
- 목록: 지역, 주제, 희망 직군, 모집 중 여부 필터 / 최신순·마감임박순 정렬
- 카드 표시: 제목, 지역, 요일·시간, 정원(현재/최대), 희망 직군 태그, **입장 기준 배지**, 주최자 지표
- 상세: 소개, 세션 일정, 참여자 목록(닉네임 + 출석 지표), 참여 신청 버튼

### 4.4 참여 신청
1. 신청 → 검증 통과 시 **즉시 참여 확정** (주최자 승인·대기 없음) → 채팅방 입장
2. **검증 순서**: 정원 → 이용 제한 상태 → 입장 기준(출석률/신규) → 중복 신청
3. 내 직군이 희망 직군과 다르면 **안내 문구만 표시**(막지 않음)
4. **정원 동시성**: 마지막 1자리에 동시 신청이 와도 초과 확정 금지 (락/원자 처리)
5. 참여자가 채팅방을 나가면 참여 취소로 처리. 취소 시점에 따라 출석 지표에 영향 (4.6)

### 4.5 세션 & 알림
- 세션 생성 시 참여자에게 알림, 변경/취소 시 즉시 알림
- 일정 알림: **전날**, **1시간 전**, **체크인 오픈 시점**
- 채널: 웹 푸시(PWA) + 이메일 (초기). 알림톡은 사용자 증가 후 검토
- 알림 수신 설정(채널별 on/off)

### 4.6 출석 체크 (핵심)
**원칙: 본인 체크인이 기본. 주최자도 참여자와 동일하게 체크인하며, 주최자가 노쇼를 일방적으로 확정하지 못함**

체크인 방식 (GCOO처럼 위치 기반, 대면 전용)
- 체크인 순간 **참여자 본인 휴대폰 위치**가 **스터디 장소 반경 내**(제안 150m, 실내 GPS 오차 고려)이면 체크인 버튼 활성화. 위치는 체크인 순간에만 사용
- 주최자도 동일하게 체크인
- **주최자 미도착 규칙**: 시작 + 30분까지 주최자 체크인이 없으면 세션을 '무효' 처리 → 참여자는 노쇼 아님, 주최자 불참만 기록 (QR 방식의 "주최자 노쇼 시 전원 노쇼" 문제 해결)
- GPS 실패 대비 보조 수단: 주최자가 보여주는 일회용 코드 입력 (주최자 체크인 완료 시에만 유효). **위치 권한을 거부했거나 GPS가 실패한 경우의 유일한 대체 수단**이며, 코드로 체크인해도 출석·지각 판정은 시각 기준으로 동일하게 적용
- 체크인 가능 시간(설정값): 시작 10분 전 ~ 시작 후 30분
- 세션 중 확인 핑 없음. 출석 여부는 체크인 한 번으로 판정

자동 판정 (제안값)
| 상태 | 조건 |
|---|---|
| 출석 | 시작 시각 + 10분 이내 체크인 |
| 지각 | 시작 + 10분 초과 ~ 30분 이내 체크인 |
| 노쇼 후보 | 주최자는 체크인했으나 해당 참여자는 체크인 없음 → 세션 종료 후 자동 판정 |
| 노쇼 | 통지 후 이의 기간(48시간) 경과, 또는 이의 기각 |
| 세션 무효 | 주최자 미도착. 참여자 지표 영향 없음, 주최자는 -1 (4.13) |
| 사전 취소 | 시작 **3시간 전까지** 참여 취소 — 지표에 영향 없음 |
| 직전 취소 | 시작 **3시간 이내** 참여 취소 — 노쇼보다 가벼운 감점으로 집계 |

- 사전/직전 취소 기준은 주최자와 같은 **3시간**으로 통일 (v0.1의 24시간, v0.2의 2시간에서 변경)
- 주최자의 수동 변경은 전부 로그로 남김

### 4.7 출석 지표 (사람 평가 없음)
- 표시 형태: **"출석률 92% · 최근 10회 중 노쇼 0회 · 지각 1회"**
- 계산 (제안): 최근 10회 세션 기준
  `출석률 = (출석 + 지각) / (출석 + 지각 + 노쇼 + 직전취소)` · 사전 취소는 분모 제외
- 주최자 귀책(세션 무효, 주최자 포기)으로 진행되지 않은 세션은 **모든 참여자의 분모에서 제외**
- **신규 배지**: 집계 대상 세션이 3회 미만이면 숫자 대신 "신규"
- 입장 기준 옵션 (주최자 설정)
    - 최소 출석률 N% (예: 70)
    - 신규 허용 / 신규 불허 (**기본값: 허용**)
- 점수 변동 이력은 이벤트로 저장하고, 사용자 집계값은 캐시 (정책 변경 시 재계산 가능)

### 4.8 참여자 제재 (단계별, 제안값)
| 단계 | 조건 | 효과 |
|---|---|---|
| 경고 | 노쇼 1회 | 안내 알림 |
| 제한 | 최근 5회 중 노쇼 2회 | 7일간 새 스터디 참여 신청 불가 (기존 스터디는 유지) |
| 정지 | 제한 후 재발 / 최근 10회 중 노쇼 4회 | 14일 이용 정지 |

### 4.9 이의 신청
- 대상: 노쇼/지각 판정. 기한 48시간, 사유 텍스트 + (선택) 증빙
- 처리: 1차 주최자 의견 → 운영자 최종 결정. 인정 시 기록 정정 + 지표 재계산
- 악용 방지: 동일 사용자 이의 반복 기각 시 제한

### 4.10 마이페이지
- 내 지표, 참여/주최 중인 스터디, 다가오는 세션, 지난 출석 기록, 알림 설정, 이의 신청 내역

### 4.11 신고/운영
- 스터디·사용자 신고(부적절한 모집 등), 관리자 목록·처리 화면

### 4.12 채팅 (MVP 포함)
- 스터디당 채팅방 1개. 스터디 생성 시 주최자와 함께 만들어지고, **참여가 확정된 사람만** 입장·열람 (나가기/강퇴 시 접근 차단)
- 텍스트 메시지 중심, 공지(주최자) 고정, 읽지 않음 표시, 새 메시지 알림
- 메시지 저장(DB) 및 이전 대화 페이징 조회
- 신고·차단(메시지 단위) 최소 기능
- **채팅방 나가기의 의미**
    - 참여자가 나가면 → 참여 취소 (4.4, 4.6)
    - 주최자가 나가면 → 주최 포기. **승계 규칙 적용** (4.13)
- 구현 방향: WebSocket(STOMP) + 단일 서버 시작, 서버 증설 시 Redis pub/sub

### 4.13 주최자 지표와 승계

**A. 주최자 포기(채팅방 나가기)와 승계**
| 상황 | 처리 |
|---|---|
| 채팅방에 **주최자만** 남음 | 스터디의 예정 세션은 **파투(취소)**. 영향받는 참여자가 없으므로 감점 없음 |
| 채팅방에 **참여자가 1명 이상** 남음 | 남은 참여자 중 **무작위 1명**이 새 주최자가 됨 (승계). 장소·일정·입장 기준 등 설정은 그대로 승계 |

- 주최자는 스터디 운영상 역할이 크지 않으므로 **수락/거절 없이 자동 배정**한다 (확정). 새 주최자에게는 알림만 보낸다
- 추첨 대상은 추첨 시점에 채팅방에 남아 있는 참여자로 한정한다. 주최자 나가기와 참여자 나가기가 겹쳐도 대상자는 한 명으로만 정해져야 한다 (8장)
- 배정 후에는 일반 주최자 규칙이 그대로 적용된다 (불참 시 -1 등)
- 승계 기록은 남기되, 새 주최자의 지표에는 승계 자체가 불이익이 되지 않음

**B. 주최자 감점 (단일 규칙)**
- **다음 세션 시작 3시간 이내**에 주최자가 채팅방을 나가거나, 주최자 미도착으로 세션이 무효가 되면 **-1점** (영향받는 참여자가 있을 때만)
- 그보다 일찍 나가는 경우는 감점 없음 (횟수는 표시)
- 점수는 90일 롤링 후 소멸

**C. 주최자 제재 (90일 내 합계, 제안값 — 기존 3/5/8에서 축소, 확인 필요)**
| 합계 | 효과 |
|---|---|
| 2점 | 경고 |
| 3점 | 새 스터디 개설 7일 제한 |
| 5점 이상 | 새 스터디 개설 30일 제한 + 운영자 검토 |

- 자동 영구정지 없음. 불가항력 면제, 참여자 신고 기반 노쇼 확정은 MVP에서 제외(이의 신청 4.9로 갈음)

**D. 표시와 참여자 보호**
- 표시: "주최 N회 중 직전 이탈 N회". 주최 5회 미만은 퍼센트 대신 건수만 표시
- 주최자 귀책으로 진행되지 않은 세션은 참여자의 출석률 분모에서 제외, 참여자 노쇼·취소 기록 없음, 변경 시 즉시 알림

## 5. 화면 목록

1. 랜딩 / 로그인
2. 온보딩(직군·지역 입력)
3. 스터디 목록(필터)
4. 스터디 상세
5. 스터디 만들기
6. 내 스터디 관리 (참여자 목록, 세션 관리)
7. 세션 체크인 화면 (참여자: 위치 기반 체크인 / 주최자: 체크인 + 보조 코드 표시)
8. 채팅방
9. 새 주최자 알림 화면 (승계 안내)
10. 마이페이지 (지표·기록)
11. 이의 신청
12. 알림 센터 / 설정
13. 관리자: 이의 신청 큐, 신고 큐, 사용자 제재 관리

## 6. 핵심 흐름

**참여**: 목록 → 상세 → 신청 → 참여 확정(즉시) → 채팅방 입장
**출석**: 전날/1시간 전 알림 → 체크인 오픈 알림 → 장소 도착 후 체크인 → 출석/지각 자동 기록
**노쇼**: 미체크인 → 노쇼 후보(자동) → 참여자에게 통지(이의 48h) → 확정 → 지표 반영·제재 판정
**이의**: 통지 → 이의 신청 → 주최자 의견 → 운영자 결정 → 지표 재계산
**주최자 포기**: 주최자가 채팅방 나가기 → (참여자 없음) 파투 / (참여자 있음) 남은 참여자 중 무작위 1명이 자동으로 새 주최자 (알림 발송) → (시작 3시간 이내였다면) 전 주최자 -1

## 7. 범위 밖 (MVP 제외)

- 비대면(온라인) 스터디와 Zoom/Meet 연동, 세션 중 확인 핑, 온라인/오프라인 출석률 분리 표시 (이후 사용자 리뷰를 보고 별도 종류로 추가 검토)
- 탈퇴 후 이력 보관·재가입 방지, SMS 인증
- 앱 출시, 추천 알고리즘, 결제/장소 예약, 알림톡
- 사용자 간 평가(영구 제외)

## 8. 비기능 요구

- 정원 마감 동시 신청 정합성, 알림 발송 신뢰성(재시도), 점수 변동 감사 로그
- 주최자 승계 시 동시성: 주최자 나가기와 참여자 나가기가 겹쳐도 승계 대상이 한 명으로만 정해져야 함
- 위치 정보는 체크인 순간만 사용·저장 최소화 (개인정보 처리방침 필요)
- 정책 수치(시간창, 임계값, 감점)는 설정으로 분리

## 9. 결정 현황

**확정**: 지도·장소 API는 카카오맵, 초기 규모는 소규모(수원 4개 구, 서버 1대), 위치 권한 거부·GPS 실패 시 대체 수단은 일회용 코드만(주최자 체크인 후 유효), 소셜 로그인(카카오·구글), 채팅 MVP 포함, 지역 구 단위, 시작 지역 수원시(4개 구), 위치 기반 체크인(반경 150m, 설정값), 주최자는 언제든 포기 가능하되 다음 세션 3시간 이내 포기만 감점(승계로 배정된 새 주최자도 동일), **대면 스터디 전용 MVP**, 핑 없음, 참여 신청은 주최자 승인 없이 자유 신청, 사전/직전 취소 기준 3시간, 주최자 감점은 3시간 이내 이탈 -1 단일 규칙, 채팅방 나가기 기반 주최자 승계(남은 참여자 중 무작위 자동 배정, 수락/거절 없음), 채팅방은 스터디 단위, 프론트 Next.js

**운영 후 과제** (서비스 핵심 기능이 아니므로 핵심 기능 완성 후 검토)
- 탈퇴 후 이력 보관과 재가입 어뷰징 대응. 필요해지면 `reports/스터디 서비스 신뢰 설계 리서치.md`의 하이브리드안(HMAC 해시 + 제재 요약 6개월 보관, SMS 인증 단계 확장)을 참고. 도입 시점에 개인정보 보호법 적합성을 변호사 또는 개인정보위(118)에 확인
- 비대면 스터디 추가 여부 (사용자 리뷰 기반). 추가 시 Zoom/Meet 연동과 출석 확인 방식은 보고서의 온라인 출석 조사를 참고
