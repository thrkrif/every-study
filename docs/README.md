# 문서 지도

이 프로젝트의 문서를 어디서 시작해 어디로 이어 읽는지 정리한다. 에이전트와 사람 모두 **`AGENTS.md` → 이 문서 → 필요한 문서** 순서로 들어간다. 전부 읽지 말고 상황에 맞는 것만 읽는다.

## 1. 상황별로 무엇을 읽나

## 2. 계층 (위가 원본, 아래는 위를 근거로 한다)

```
PRD  (무엇을, 수치)
 └─ ARCHITECTURE  (어떻게: 구조·원칙)  ── adr/  (결정과 근거)
     └─ DATA-MODEL · API  (데이터·API 명세)
         └─ PLAN  (마일스톤·작업 체크리스트)
             └─ 코드
```

- 위 문서가 바뀌면 아래 문서를 함께 확인한다.
- 아래 문서는 **위 문서를 반복해서 쓰지 않고 링크**한다 (3장 규칙 1).

## 3. 작성 규칙

1. **한 사실은 한 곳에만 쓴다.** 정책 수치(시간, 반경, 점수 등)는 PRD가 원본이다. 다른 문서는 값을 복사하지 않고 `PRD 4.6`처럼 위치를 가리킨다. 복사본은 반드시 어긋난다.
2. **문서 머리에 관계를 선언한다** (4장). 위치와 관계는 사람이 기억하지 않고 머리말로 남긴다.
3. **파일은 필요해질 때 만든다.** 비어 있는 디렉토리와 "추후 작성" 문서를 미리 만들지 않는다.
4. **ADR은 번호로 쌓고 고치지 않는다.** 결정을 바꾸면 새 ADR을 쓰고 이전 것의 `status`를 `superseded`로 바꾼다 (오탈자·링크 수정은 허용).
5. 링크는 상대 경로를 쓴다. 문서를 옮기면 링크를 함께 고친다.
6. **아래 문서는 위 문서에 없는 기능을 정하지 않는다.** API·DATA-MODEL·PLAN을 쓰다가 PRD에 없는 기능이나 쓰임새가 필요해 보이면, 그 문서에 바로 적지 않고 PRD를 먼저 고치거나 [PLAN](PLAN.md) 7장에 X로 등록해 결정을 받는다. 충돌은 결정 과정에서 드러나지만 조용히 더해진 기능은 드러나지 않아서, 한쪽 문서만 따른 작업이 어긋난다 (PLAN T-073). API는 화면 열([API](API.md) 1장)로 이것을 검사한다.

## 4. 문서 머리말 (front matter)

모든 `docs/**/*.md`는 맨 위에 YAML 머리말을 둔다.

```yaml
---
status: draft            # draft | confirmed | superseded
version: "0.1"           # 다른 문서가 고정(pin)해서 참조하는 문서만 (PRD, ARCHITECTURE 등)
based_on:                # 근거로 삼은 상위 문서와 그 시점의 버전
  - docs/PRD.md@0.3
covers:                  # 이 문서가 설명하는 코드 경로 (코드가 생긴 뒤에 추가). ** 는 하위 전체
  - backend/src/main/java/.../study/**
---
```

| 필드 | 의미 | 쓰임 |
|---|---|---|
| `status` | 확정 여부 | 초안을 확정 사실처럼 인용하지 않기 |
| `version` | 이 문서의 버전. 내용이 의미 있게 바뀔 때 올린다 | 아래 문서가 `based_on`으로 고정 |
| `based_on` | `경로@버전` 목록 | 상위 문서 버전이 올라가면 이 문서를 "오래됨"으로 표시 |
| `covers` | 설명 대상 코드 경로 | 코드가 바뀐 PR 에서 이 문서가 그대로면 검사가 알려 준다 |

### 검사 (`tools/docs-check.sh`)

CI(`docs` job)가 모든 `docs/**/*.md`를 검사하고, 로컬 pre-commit은 같은 검사를 **경고로만** 보여 준다. `covers` 검사는 비교할 기준 브랜치가 있을 때만 한다 (CI는 PR의 대상 브랜치, pre-commit은 `origin/develop`. 직접 실행: `bash tools/docs-check.sh --base origin/develop`).

| 검사 | 실패 조건 |
|---|---|
| 머리말 | 없음, 닫히지 않음, `status` 없음·잘못된 값, `version` 형식 오류 |
| `based_on` | 형식이 `경로@버전`이 아님, 대상 없음, 대상에 `version` 없음, **버전이 다름(오래됨)** |
| 링크 | 상대 경로 링크의 대상이 없음 (코드 블록·인라인 코드·외부 링크 제외) |
| `covers` | 기준 브랜치에서 갈라진 뒤 바뀐 파일이 어떤 문서의 `covers`에 해당하는데, 그 문서는 바뀌지 않음 |
| 화면 추적 | `API.md` 엔드포인트 표에 "화면" 열이 없음, 칸이 비었음, 값이 `PRD.md` 5장에 없는 화면 번호임(`공통`, `없음: <이유>`는 허용). 두 문서가 있을 때만 검사 |

- **오래됨**이 뜨면: 상위 문서의 변경을 확인하고 이 문서를 고친 뒤 `based_on`의 버전을 올린다. 상위 문서의 `version`을 올리는 PR은 이 때문에 하위 문서를 함께 확인하게 된다.
- 한계: 내용을 바꿨는데 `version`을 올리지 않은 경우는 알 수 없다. 의미 있는 변경(수치·규칙·구조)이면 `version`을 올리는 것이 규칙이다.
- **`covers`**가 뜨면: 그 문서가 바뀐 코드와 같은지 확인하고 같은 PR에서 고친다. 확인했는데 고칠 내용이 없으면(이름만 바꾼 리팩터링, 테스트만 추가 등) PR의 커밋 메시지 본문에 아래 줄을 넣어 건너뛴다. 사유는 반드시 적고, 건너뛴 문서와 사유는 검사 출력에 남는다.

  ```
  Docs-Unchanged: 메서드 이름만 바꿔 문서의 설명이 달라지지 않음
  ```

  - 이 줄은 PR 전체의 `covers` 검사를 건너뛴다 (다른 검사는 그대로). 줄 맨 앞에 써야 하고, PR의 커밋 중 하나에만 있으면 된다.
  - `covers` 패턴: `**`는 `/`를 포함한 아무 문자열, `*`는 `/`를 뺀 문자열이다. 디렉토리 전체는 `경로/**`로 쓴다.
  - 한계: 문서 파일이 바뀌었는지만 본다. 맞게 고쳤는지는 리뷰가 본다. 패턴을 넓게 잡으면(예: 소스 전체) 거의 모든 PR에서 뜨므로, 문서가 실제로 설명하는 경로만 적는다.

문서별 상태·버전은 각 문서의 머리말이 원본이다 (이 문서에 표로 다시 적지 않는다).
