# DESIGN — 화면 디자인 원칙과 토큰

- 이 문서는 **화면이 어떻게 보이고 어떻게 말하는지**의 원본이다. 무엇을 보여 줄지(필드, 정책 수치)는 [PRD](PRD.md), 화면 목록은 PRD 5장이 원본이다. 여기에는 정책 수치를 쓰지 않고 위치만 가리킨다.
- 색·간격 같은 토큰 값은 이 문서가 원본이고, 코드(CSS 변수)는 이 값을 옮긴 것이다. 값을 바꾸면 이 문서를 먼저 고친다.
- 초안이다. M1 화면(로그인, 온보딩, 목록, 상세, 개설)을 기준으로 쓰고, 나머지 화면은 같은 규칙으로 각 프론트 작업에서 확장한다 ([PLAN](PLAN.md) T-069).

## 1. 서비스 성격

- **누가 쓰는가**: 취업을 준비하며 오프라인 스터디를 찾는 사람. 대부분 휴대폰으로, 이동 중이나 카페에서 한 손으로 쓴다.
- **화면의 일**: 스터디를 비교해 고르고(일시·장소·정원·주최자 신뢰), 신청하고, 당일 체크인한다. 이 서비스는 "나오는 사람끼리 만나게 해 주는 것"이라 신뢰와 시간을 읽기 쉽게 보여 주는 것이 전부다.
- **톤**: 차분하고 정직하다. 재촉하거나 겁주지 않는다. 가볍고 감성적인 모임 앱과 다르게, 약속을 지키는 사람들의 도구처럼 보여야 한다.

## 2. 원칙

1. **시간과 사람 수가 가장 크게 읽힌다.** 일시와 정원은 제목 다음 위계다. 장식 이미지는 없다.
2. **신뢰는 점수 하나가 아니라 기록으로 보여 준다.** "출석률"과 최근 기록을 함께 보여 줘서 왜 그런 수치인지 읽히게 한다 (표시 항목은 PRD 4.7).
3. **한 화면에 행동 하나.** 화면마다 강조색 버튼은 하나, 하단에 고정한다.
4. **상태는 색만으로 구분하지 않는다.** 모양과 글자를 함께 쓴다.
5. **움직임은 사용자의 행동에 답할 때만 쓴다.** 진입 애니메이션과 호버 효과는 넣지 않는다.

### 레퍼런스

레퍼런스 서비스는 robots.txt와 약관상 자동 열람이 막혀 있어, 사람이 직접 찍은 캡처와 회사가 공개한 문서만 본다 ([PLAN](PLAN.md) T-069 도구 주의). 캡처 원본은 저장소에 두지 않는다.

| 레퍼런스 | 고른 이유 | 입력 | 상태 |
|---|---|---|---|
| 모임 앱 한 곳 | 오프라인 모임의 목록·상세·신청 흐름이 우리와 같다 | 사람이 찍은 모바일·웹 캡처 | 분석함 |
| 당근 모임 (일정) | 동네 단위로 모여 공부하는 일정이 실제로 열린다. 주최·참여자·마감 표시가 우리와 가장 가깝다 | 캡처 5장 (상세 모집 중·마감, 참여자, 내 일정, 채팅방) | 분석함 |
| 플랩풋볼 | 정원이 정해진 오프라인 경기에 혼자 신청한다. 시간 중심 목록, 마감 숨기기, 신청 확인·완료, 지각 알림이 있다 | 캡처 6장 (목록, 상세 모집 중·마감, 신청 확인, 신청 완료, 신청 후 상세) | 분석함 |
| 네이버 예약 | 날짜·시간 고르기와 입력 단계의 정보 위계. 우리 개설 흐름과 닮았다 | 캡처 2장 (날짜·시간 선택, 입력) | 분석함 |
| 플랩풋볼 PC 웹 | 웹을 먼저 만들고 앱을 낸 서비스. 같은 화면이 PC와 휴대폰에서 어떻게 바뀌는지 본다 | PC 캡처 3장 (100%·75% 배율의 첫 화면과 목록) | 분석함 (반응형) |
| 당근 SEED Design | 공개된 디자인 시스템(Apache-2.0). 토큰 원본을 하나 두고 각 플랫폼 코드가 그것을 옮기는 구조를 참고했다 | 공개 저장소 문서 | 구조만 참고 |

### 캡처 분석

캡처는 2026-11-18에 찍었다. 각 서비스의 색·사진·일러스트·문구는 옮기지 않고 정보 순서와 상태 표현만 적는다.

**정보 순서**

| 화면 | 당근 모임 | 플랩풋볼 | 네이버 예약 |
|---|---|---|---|
| 목록 | 날짜 블록(월·일·요일) → 제목 → 시각·인원 → 상태 칩. 참여 중 / 다가오는 / 종료된 일정을 구역으로 나눈다 | 상단 날짜 띠 → 필터 칩(내 지역, 필터, 마감 가리기) → 행마다 **시각이 가장 크게**, 장소, 경기 방식 | - |
| 상세 | 주최자(동네·작성 시점) → 상태 + 제목 → 일시 → 장소 링크 → 소개 → 조건 칩(누구나 참여 가능 등) → 장소 카드(이름·거리·주소) → 참여자 n/m과 가로 목록(주최 표시) → 사실 칩(진행 횟수, 재참여자 수) | 사진 → 일시 → 장소 + 지도 → 가격 → 남은 자리 막대 → 경기 정보 | - |
| 신청 | 버튼 한 번 | 신청 정보 요약 카드(일시·장소·가격) → 동의 문구 → 신청 버튼 | 선택한 날짜·시각을 위에 고정 → 달력 → 오전/오후로 묶은 시각 칸 격자 → 닫기 / 다음 |
| 신청 뒤 | 하단이 참여 취소(보조) + 채팅방(주요)으로 바뀐다 | 완료 화면: 완료 한 줄 + **당일 몇 분 전까지 오라는 안내** → 일시(캘린더 저장) → 장소(지도) → 조건 칩 → 다음 행동(라커룸) + 공유·홈. 상세에는 시작까지 남은 시간과 "지각 알리기" | 업체 확인 뒤 확정된다는 안내 띠, 필수 표시, 글자 수 세기, 조건을 채우기 전까지 비활성 신청 버튼 |

**정원·대기 표시**

- 당근: 참여자 수를 "4/4"처럼 숫자로 크게 쓰고, 마감되면 제목 앞 상태 글자가 바뀐다. 마감 뒤 대기 기능은 보이지 않는다.
- 플랩: 남은 자리를 빨간 막대와 "n자리 남았어요" 문구로 재촉한다. 마감되면 막대가 가득 차고, **빈자리 알림 받기**를 주며, 비활성 버튼 위에 다른 경기를 보라는 한 줄을 둔다.
- 목록에서 마감을 기본으로 보이게 두고 "마감 가리기"로 숨긴다(플랩). 우리는 반대로 기본은 모집 중만, "마감 포함"으로 펼친다 (PRD 4.3).

**PC 배치 (플랩 PC 웹)**

- 상단 한 줄: 왼쪽 로고, 오른쪽 아이콘 메뉴(검색, 알림, 관심, 일정, 내 정보). 그 아래 서비스 구분 탭. 하단 탭바는 없다.
- 목록: **왼쪽 필터 열**(제목별 칩 묶음을 세로로 쌓음) + **오른쪽 목록**(날짜 띠, 마감 가리기, 지도 전환, 행 목록). 휴대폰의 가로 칩 한 줄이 PC에서는 왼쪽 열로 펼쳐진다.
- 본문은 최대 폭(약 1170px)으로 가운데 고정되고, 더 넓은 화면에서는 양옆이 빈다. 글자·칩 크기는 휴대폰과 같다.

**신뢰 표현**

- 당근: 점수 없이 **사실 문장 칩**으로 보여 준다(이 주최자의 진행 횟수, 다시 참여한 사람 수).
- 플랩: 참여자 수준 분포를 막대그래프로 요약한다. 개인 기록은 보이지 않는다.
- 둘 다 개인의 출석·지각 기록은 보여 주지 않는다. 출석 기록 줄(3장)은 우리만의 차이로 둔다.

### 가져온 것과 버린 것

레퍼런스에서는 **구조만** 가져왔고, 시각 요소(색, 일러스트, 문구, 로고)는 복제하지 않았다.

| 가져온 것 | 우리 방식 |
|---|---|
| 한 화면에 질문 하나, 상단 진행 막대, 하단 고정 "다음" | 개설·온보딩 입력 흐름 (6장) |
| 아이콘 칩 한 줄로 요약한 일시·정원 | 상세 요약줄 (6장) |
| 하단 고정 CTA, 하단 탭바 가운데 개설 버튼 | 5장 컴포넌트 |
| "참여 중 현재/정원" 숫자 강조와 참여자 가로 목록 | **좌석 줄** (3장)로 발전 |
| 빈 화면 = 아이콘 + 한 줄 + 다음 행동 안내 | 7장 문구 규칙 |
| 알림 권한 요청 전에 무엇을 알려 주는지 먼저 설명 | 웹 푸시 권한 화면 |
| 목록 행에서 시각을 가장 크게 (플랩) | 목록 카드 시각 강조 (6장) |
| 마감 숨기기/보이기 칩 (플랩) | 목록 필터 줄의 "마감 포함" 칩 (6장) |
| 조건 칩 (당근) | 상세의 입장 기준·희망 직군 칩 |
| 참여자 n/m과 가로 목록, 주최 표시 (당근) | 상세 참여자 구역, 좌석 줄과 함께 |
| 점수 대신 사실 문장 칩 (당근) | 주최자 사실 칩(주최 횟수 등)을 출석 기록 줄 옆에 |
| 마감 상태를 글로 설명하고 다음 행동 제시 (플랩) | 정원이 차면 "대기하기"와 그 이유 한 줄 |
| 신청 뒤 하단이 보조 + 주요 두 버튼으로 바뀜 (당근) | 참여 중이면 참여 취소(보조) + 채팅(주요) |
| 완료 화면에 당일 해야 할 일 안내 (플랩) | 참여 완료 화면에 체크인 시간창 안내 (6장) |
| 신청 전 요약 카드 (플랩), 단계 흐름의 이전/다음 (네이버) | 개설 마지막 단계 요약, 하단 이전/다음 |
| 선택한 값을 위에 고정한 날짜·시각 고르기, 오늘 표시, 지난 날 흐림 (네이버) | 개설의 일시 단계 (6장) |
| 필수 표시, 글자 수 세기, 다 채우기 전 비활성 버튼 (네이버) | 입력 규칙 (5장) |
| 날짜 블록(월·일·요일) 목록과 참여 중 / 다가오는 / 종료 구역 (당근) | 내 스터디 화면 (M2) |

| 버린 것 | 이유 |
|---|---|
| 사진 중심 카드, 큰 배너, 이모지 제목 | 스터디에는 사진이 없고, 정보 비교가 목적이다 |
| 신뢰를 점수 하나로 요약 | 왜 그 점수인지 보이지 않는다 |
| "신청률이 올라가요" 같은 수치 유도 문구 | 차분한 톤과 맞지 않는다 |
| 유형별 색(빨강·파랑·초록), 광고·결제·팔로우·피드 | 유형이 하나이고 범위 밖이다 (PRD 7장) |
| 빨간 남은 자리 막대와 불 아이콘 (플랩) | 재촉이다. 우리 정원은 작아서 좌석 줄이 숫자를 더 정확히 보여 준다 |
| 상태를 제목 앞 색 글자로만 표시 (당근) | 색에 기대고 위치가 제목마다 달라진다. 상태 칩을 쓴다 |
| 공감·관심·조회 수, 하트 (당근, 플랩) | 고르는 데 도움이 되지 않는 인기 지표다 |
| 큰 사진, 지도 이미지 머리 (플랩, 당근) | 스터디에는 사진이 없다. 장소는 글과 지도 링크로 충분하다 |
| 나이대("내 또래") 표시 (당근) | 나이를 받지 않는다 |
| 수준 분포 그래프 (플랩) | 수준 개념이 없다 |
| 흐르는 글자 띠, 가격·쿠폰·캐시 (플랩) | 움직임 원칙과 범위에 맞지 않는다 |

## 3. 시그니처: 좌석 줄과 출석 기록 줄

화면에서 기억에 남는 요소는 이 둘이다. 나머지는 조용히 둔다.

**좌석 줄 (정원 표시)** — 정원만큼의 작은 칸을 한 줄로 늘어놓고, 참여자 수만큼 채운다. 숫자 "3/6"을 옆에 함께 쓴다.

```
■■■□□□  3/6명        모집 중, 자리 남음
■■■■■■  6/6명        마감 (채움은 중립색)
■■■■□□  4/6명        내가 참여 중이면 내 칸에 점 표시
```

- 채운 칸: 기본색. 빈 칸: 윤곽선만. 주최자 칸은 잉크색으로 한 칸 구분한다.
- 마감은 오류가 아니므로 빨간색을 쓰지 않는다. 모든 칸을 중립 회색으로 채운다.
- 참여가 확정되면 내 칸이 채워지는 짧은 전환을 한 번만 보여 준다 (사용자 행동에 대한 응답).
- 접근성: 줄 전체에 `aria-label="정원 6명 중 3명 참여"`를 단다. 칸은 장식으로 숨긴다.

**출석 기록 줄 (신뢰 표시)** — 최근 세션 기록을 모양으로 한 줄에 보여 준다. 몇 회를 보여 줄지는 PRD 4.7이 정한다.

```
출석률 92%    ■■■■■■■■▲■   (최근 기록: 출석 ■, 지각 ▲, 노쇼 ✕, 기록 없음 □)
```

- 모양과 색을 함께 쓴다 (출석 = 채운 네모·초록, 지각 = 삼각·황색, 노쇼 = 엑스·빨강).
- 기록이 없는 새 사용자는 "신규"로 표시하고 빈 칸을 보이지 않는다. 입장 기준에 신규 허용이 걸리면 PRD 4.2·4.7을 따른다.
- 접근성: `aria-label="최근 10회 중 출석 8회, 지각 1회, 노쇼 1회"`처럼 숫자를 글로 제공한다.

## 4. 토큰

### 색

대비는 WCAG AA(본문 4.5:1) 기준으로 계산해 확인한 값이다. 새 조합을 쓰면 코드에서 다시 계산한다.

| 이름 | 값 | 용도 | 대비 |
|---|---|---|---|
| `ink` | `#1F2937` | 본문·제목 | 흰색 위 14.7 |
| `ink-sub` | `#5B6575` | 보조 글자 | 흰색 위 5.9, 배경 위 5.5 |
| `paper` | `#F5F6F8` | 화면 배경 | - |
| `surface` | `#FFFFFF` | 카드·입력 배경 | - |
| `line` | `#E3E6EC` | 1px 구분선·윤곽선 | 글자에 쓰지 않음 |
| `primary` | `#2B4FCC` | 주요 버튼·링크·채운 칸 | 흰색 위 6.8 |
| `primary-tint` | `#E8EDFB` | 선택됨·대기 배경 | `primary` 글자 5.8 |
| `ok` / `ok-bg` | `#18794E` / `#E7F5EE` | 출석 | 4.8 |
| `late` / `late-bg` | `#9A5B00` / `#FDF1DC` | 지각 | 4.9 |
| `bad` / `bad-bg` | `#B42318` / `#FCE9E7` | 노쇼·오류 | 5.6 |
| `neutral-bg` | `#EDEFF3` | 마감·종료 | `ink-sub` 글자 |
| `disabled` | `#9AA3B2` | 비활성 버튼, 마감된 좌석 칸 | 글자의 유일한 정보로 쓰지 않음 |

- 강조색은 `primary` 하나다. 같은 화면에서 `primary` 채움 버튼은 하나만 둔다.
- 비활성 요소는 `line`보다 진한 `disabled`를 쓰되 글자의 유일한 정보로 쓰지 않는다 (비활성 사유는 옆 글자로 알린다, 5장).
- 다크 모드는 후속이다 (10장).

### 글꼴

- **본문·제목 모두 한 글꼴 계열**을 쓴다: Pretendard (가변 폰트, 자체 호스팅). 한글과 숫자가 같은 굵기 체계에서 고르게 읽히고, 낮은 해상도 화면에서도 획이 무너지지 않는다. 개성은 글꼴이 아니라 위계와 시그니처 요소에서 만든다.
  - 라이선스는 SIL Open Font License 1.1이다. 글꼴만 따로 파는 것을 빼면 상업적 사용·수정·재배포가 된다.
  - npm 패키지 `pretendard`의 가변 woff2 파일 하나를 `next/font/local`로 읽는다 (`frontend/src/app/fonts.ts`). 외부 CDN을 쓰지 않는다.
  - 파일이 약 2MB다. 첫 화면 무게가 문제가 되면 쓰는 글자만 남긴 부분 글꼴로 바꾼다 (10장).
- 숫자(시각, 정원, 출석률)는 항상 `font-variant-numeric: tabular-nums`로 자릿수를 맞춘다.
- 한 줄 길이는 모바일 폭에서 자연스럽게 한 줄 40자 안팎이 되도록 둔다.

| 이름 | 크기/행간 | 굵기 | 용도 |
|---|---|---|---|
| `time` | 28/32 | 700 | 상세 상단 일시 |
| `title` | 22/30 | 700 | 화면 제목 |
| `heading` | 17/24 | 600 | 구역 제목, 카드 제목 |
| `body` | 15/24 | 400 | 본문 |
| `label` | 13/20 | 500 | 칩, 보조 정보 |
| `caption` | 12/16 | 400 | 최소 크기. 이보다 작게 쓰지 않는다 |

### 간격·모양

- 간격은 4px 기준이다: 4, 8, 12, 16, 20, 24, 32, 40. 화면 좌우 여백은 16, 구역 사이는 24~32.
- 모서리는 위계에 따라 다르다. 같은 값을 모두에 쓰지 않는다: 칩 완전 둥근, 입력·버튼 12, 카드 16, 하단 시트 위쪽 24, 좌석 칸 3.
- 카드는 그림자 대신 1px `line` 윤곽선과 배경 차이로 구분한다. 그림자는 위에 떠 있는 요소(토스트, 시트)에만 쓴다: `0 8px 24px` `ink` 16%.
- 터치 대상은 최소 44×44, 주요 버튼 높이는 52. 하단 고정 영역은 기기 안전 영역(`safe-area`)을 더한다.
- **반응형 웹**이다. 디자인은 360px(휴대폰)에서 시작하고, 폭이 넓어지면 배치를 바꾼다 (6장 "폭에 따른 배치").

| 구간 | 폭 | 좌우 여백 | 본문 최대 폭 |
|---|---|---|---|
| 휴대폰 | ~767px | 16 | 화면 폭 |
| 태블릿 | 768~1023px | 24 | 화면 폭 |
| PC | 1024px~ | 32 | 1120px, 가운데 정렬 |

- 입력 화면(로그인, 온보딩, 개설)은 어느 폭에서나 최대 480px 열이다. 입력칸이 화면 끝까지 늘어나면 읽고 쓰기 어렵다.

### 움직임

- 사용자의 행동에 답하는 전환(참여 확정, 시트 열기, 토스트)만 쓴다. 지속 시간은 160ms(작은 변화)와 240ms(칸 채움, 시트) 두 가지다.
- `prefers-reduced-motion`이면 전환을 끄고 즉시 상태를 바꾼다.

## 5. 컴포넌트 규칙

| 컴포넌트 | 규칙 |
|---|---|
| 버튼 | 채움(`primary`)은 화면당 하나. 보조는 윤곽선, 덜 중요한 것은 글자만. 비활성은 사유를 옆 글자로 알린다. 누르면 요청 중 상태(스피너 대신 글자 변경)를 보인다 |
| 입력 | 라벨은 입력칸 위에 항상 보인다(placeholder로 대체하지 않는다). 필수가 아닌 칸에만 "선택"을 붙인다. 길이 제한이 있으면 칸 오른쪽 아래에 글자 수를 센다. 오류는 칸 아래에 글로, `bad` 색과 아이콘을 함께. 서버 오류 코드(API 1장)를 해당 칸에 연결한다 |
| 조건 칩 | 입장 기준·희망 직군처럼 신청 조건을 글로 쓴 칩. 선택할 수 없는 정보라 `neutral-bg` 배경, 윤곽선 없음 |
| 사실 칩 | 주최자에 대한 사실 한 문장(주최 횟수 등). 점수·순위 표현을 쓰지 않는다. 표시 항목은 PRD 4.13 |
| 요약 카드 | 신청·개설 직전과 완료 화면에서 일시·장소·정원을 다시 보여 준다. `surface` 배경 + `line` 윤곽선 |
| 안내 띠 | 결과가 바로 나지 않거나 조건이 있을 때 한 줄로 미리 알린다(예: 일정은 참여자가 생기면 못 바꿔요). `primary-tint` 배경, 화면당 하나 |
| 시각 고르기 | 개설의 시각 선택. 오전/오후 → 시(12칸) → 분(단위마다) 세 줄의 선택 칩. 단위(`startMinuteUnit`)에 맞지 않는 값은 만들지 않는다. 10분 단위로 하루 144칸을 한 격자에 두면 너무 길어서 나눴다 |
| 선택 칩 | 선택됨 = `primary-tint` 배경 + `primary` 글자 + 윤곽선 + 체크 표시. 색만으로 구분하지 않는다. 하나만 고르면 라디오, 여러 개면 체크박스로 만든다(키보드·화면 낭독기) |
| 숫자 조절 | 정원·진행 시간처럼 범위와 단위가 정해진 숫자. − / + 버튼(44px)과 가운데 값. 범위 끝에서는 버튼이 막힌다 |
| 장소 고르기 | 카카오맵 키워드 검색 → 결과 목록에서 하나 → 고른 장소 카드와 작은 지도. 지도를 불러오지 못해도 장소는 고를 수 있다. 지원하는 구 밖의 장소는 이유를 쓰고 넘어가지 않는다 |
| 상태 칩 | 모집 중, 마감, 대기 가능, 진행 중, 종료. 상태 이름을 항상 글로 쓰고 색은 보조다 |
| 스터디 카드 | 3장 좌석 줄과 6장 구조. 카드 전체가 하나의 링크 |
| 소셜 로그인 버튼 | 우리 토큰이 아니라 공급자 가이드를 따른다. 카카오: 배경 `#FEE500`, 검은 말풍선 심볼, "카카오 로그인"(검정 85%), 모서리 12px. 구글: 흰 배경, `#747775` 1px 윤곽선, 글자 `#1F1F1F`, 공식 컬러 G 로고, "Google 계정으로 로그인". 로고는 공급자 배포 리소스에서 가져와 모양·색을 바꾸지 않는다(`frontend/public/auth`). 두 버튼은 같은 크기로 쌓아 어느 쪽도 더 두드러지지 않게 한다. 글꼴은 Pretendard(구글 가이드의 Google Sans는 쓰지 않는다) |
| 상단 헤더 | 모든 화면 위에 고정. 높이 56, 아래 1px `line`, `surface` 배경. 왼쪽 서비스 이름(첫 화면 = 목록 링크), 오른쪽 메뉴. 지금 메뉴는 비회원 "로그인", 회원 "스터디 만들기"(주요 글자)와 "알림"(알림 센터 링크, 안 읽은 수 배지는 없다. PLAN X-25), "로그아웃"(보조 글자색)이고, 다른 항목은 그 화면을 만드는 작업에서 더한다 |
| 하단 고정 CTA | 휴대폰에서 화면 하단에 고정, 위에 1px `line`, 좌우 16. 태블릿·PC에서는 고정하지 않고 감싸는 카드 안 아래에 둔다(6장). 상태에 따라 문구가 바뀐다 (참여하기, 대기하기, 참여 취소, 체크인하기) |
| 하단 탭바 | 항목은 적게(목록, 만들기, 내 스터디, 알림 등). 가운데 만들기는 다른 항목과 같은 크기의 윤곽 버튼으로 구분 |
| 진행 막대 | 개설·온보딩 입력 상단. 단계가 있는 흐름에서만 쓴다 |
| 토스트 | 완료 피드백 한 줄. 2~3초 뒤 사라지고 행동 문구를 반복한다("참여했어요") |
| 빈 화면 | 아이콘 + 한 줄 설명 + 다음 행동 버튼 하나 |
| 아이콘 | Lucide 한 세트만 쓴다(ISC 라이선스, 선 굵기가 고르고 한글 글자와 크기를 맞추기 쉽다). 첫 아이콘이 필요한 작업에서 `lucide-react`를 추가한다. 장식이 아니라 의미를 더할 때만 |

## 6. 화면 구조 (M1)

모든 화면은 360px 기준, 왼쪽 정렬이다. 가운데 정렬은 로그인과 빈 화면에서만 쓴다.

### 폭에 따른 배치

| 요소 | 휴대폰 (~767) | 태블릿 (768~1023) | PC (1024~) |
|---|---|---|---|
| 상단 헤더 | 로고 + 오른쪽 아이콘 몇 개 | 로고 + 오른쪽 메뉴 | 로고 + 오른쪽 메뉴(만들기, 알림, 내 스터디, 내 정보) |
| 하단 탭바 | 있음 | 없음 (메뉴는 헤더로) | 없음 |
| 목록 필터 | 제목 옆 "필터" 버튼(켠 조건 수 표시)으로 칩 묶음을 목록 위에 펼친다 | 같음 | 왼쪽 필터 열(280px)에 제목별 칩 묶음을 늘 펼친다 |
| 목록 | 카드 한 열 | 카드 2열 | 오른쪽 영역에 카드 2열 |
| 상세 | 한 열, 하단 고정 CTA | 같음 | 왼쪽 본문 + 오른쪽 따라다니는 신청 카드(일시·좌석 줄·CTA). 하단 고정 없음 |
| 입력 화면 | 화면 전체, 하단 고정 이전/다음 | 가운데 카드(480px) 안에 버튼 | 같음 |

- 칩·글자·버튼 크기는 폭과 상관없이 같다. 넓어지면 크게 키우지 않고 열을 나눈다.
- 구간 경계는 CSS 미디어 쿼리 `min-width: 768px`, `min-width: 1024px` 두 개만 쓴다.

**목록 카드**
```
┌─────────────────────────────────┐
│ 모집 중                           │
│ 내일 오전 10:00                   │  ← time 계열 강조
│ 면접 스터디 같이 준비해요            │  ← heading, 2줄까지
│ 수원역 근처 · 1.2km               │
│ ■■■□□□ 3/6명                     │  ← 좌석 줄
│ 주최 닉네임 · 출석률 92% ■■■▲■     │  ← 출석 기록 줄
└─────────────────────────────────┘
```
- 필터 묶음: 지역(전체, 내 지역, 시, 구), 주제, 희망 직군, 더 보기(내가 신청할 수 있는 스터디 — 온보딩을 마친 회원만, 마감 포함). 목록 위에 정렬(최신순, 마감임박순) (PRD 4.3).
- 첫 화면(`/`)이 목록이다. 비회원도 보고, 로그인은 헤더에서 연다.
- 카드 아래쪽 줄은 지역 · 주제 · 진행 시간, 희망 직군 칩(없으면 "직군 무관"), 주최자 닉네임과 사실 칩 문장이다. 장소 거리는 목록 API에 장소가 없어 쓰지 않는다.
- 다음 페이지는 목록 끝에 닿으면 불러오고, 같은 자리에 "더 보기" 버튼을 둔다(키보드·화면 낭독기).
- 입장 기준 배지는 카드 우상단에 글로 둔다 (PRD 4.2).
- 시각은 카드에서 가장 크게 읽힌다. 장소·진행 시간은 한 줄 보조 글자로 둔다.

**상세**
```
면접 스터디 같이 준비해요          ← title
11월 16일 월요일 오전 10:00        ← time
수원시 팔달구 ○○ (지도 링크)
■■■□□□ 3/6명 · 신청 마감 오전 9:50   ← 좌석 줄 + 마감 시각
─────────────
소개
─────────────
주최자 닉네임  출석률 92% ■■■■▲
참여자 (3)    닉네임 · 출석률 …
─────────────────────────────────
[        참여하기        ]  ← 하단 고정
```
- 소개 아래에 조건 칩(입장 기준, 희망 직군)을 둔다. 내가 조건에 맞지 않으면 CTA 대신 그 이유를 한 줄로 쓴다.
- 주최자 줄에는 출석 기록 줄과 사실 칩을 함께 둔다. 참여자는 닉네임 가로 목록이고 주최자에 "주최" 표시를 붙인다.
- 정원이 찬 경우 CTA는 "대기하기"로 바뀌고 좌석 줄은 중립색이다. CTA 위에 왜 대기인지 한 줄로 쓴다.
- 참여 중이면 하단은 "참여 취소"(보조) + "채팅"(주요) 두 버튼이다. 주요 버튼은 여전히 하나다.
- 비회원은 같은 화면을 보고, CTA는 로그인 안내로 바뀐다 (PRD 3장).
- CTA 자리는 상태에 따라 정해진다 (PLAN T-024, 규칙은 `frontend/src/lib/studyActions.ts`).

  | 상태 | 보이는 것 |
  |---|---|
  | 비회원 | "로그인하고 참여하기" 링크 |
  | 온보딩 전 | "프로필 입력하기" 링크 |
  | 모집 중 | "N자리 남았어요" + **참여하기**(주요). 희망 직군이 아니면 버튼 대신 이유 한 줄 |
  | 정원 참, 신청 열림 | 이유 한 줄 + **대기하기** |
  | 대기 중 | **대기 취소**(보조) |
  | 참여 중, 시작 전 | **참여 취소**(보조) |
  | 주최 중 | **주최 그만두기**(보조). 시작 뒤에도 나갈 수 있다 |
  | 신청 마감·시작 뒤·끝남 | 상태 한 줄만 (신청 마감, 참여 중, 진행 중, 끝남·열리지 않음) |

- 나가기는 먼저 사전 조회(`leave-preview`)로 결과를 받아 **확인 창**(`alertdialog`)에 보여 준 뒤 보낸다. 참여자는 사전/직전 취소 안내, 주최자는 승계(감점 여부 포함)·스터디 취소·시작 뒤 나가기 중 하나를 안내한다. 주요 버튼은 확인 창에서도 하나다.
- 신청·대기·나가기가 거절되면 서버 문구가 아니라 오류 코드로 정한 한 줄을 버튼 위에 `alert`로 보인다. 정원이 찼는데 신청했다면(`STUDY_FULL`) 상세를 다시 읽어 버튼이 "대기하기"로 바뀐다. `LOCK_TIMEOUT` 은 "한 번 더 눌러 주세요"이고 같은 버튼으로 다시 보낼 수 있다.
- 장소는 이름·주소 아래에 작은 지도와 "카카오맵에서 보기" 링크를 둔다. 지도를 불러오지 못하면 지도만 빠진다.
- 참여자 지표는 지금 "출석률 n%" 또는 "신규" 글로 쓴다. 출석 기록 줄은 최근 기록 순서가 API에 생기면 쓴다 (10장).

**참여 완료**: 결과 한 줄("참여했어요") 아래에 당일 할 일을 먼저 쓴다. 체크인이 시작 몇 분 전부터 열리는지(PRD 4.6) → 요약 카드(일시, 장소와 지도 링크) → 주요 버튼 "채팅 열기", 보조 "스터디 보기".

**개설 / 온보딩**: 한 화면에 질문 하나, 상단 진행 막대, 하단 고정 "이전"(보조) / "다음"(주요). 필요한 값을 채우기 전까지 "다음"은 비활성이고 이유를 옆 글자로 쓴다. 마지막 단계에서 요약 카드를 보여 주고 "만들기" 한 번으로 끝낸다. 일정·장소는 참여자가 생기면 못 바꾼다는 사실(PRD 4.2)을 해당 단계의 안내 띠로 미리 알린다.

**개설의 일시 단계**: 안내 띠(참여자가 생기면 일정·장소를 못 바꿈) → 고른 날짜·시각 한 줄 → 날짜 칩(오늘부터 개설 가능 일수까지만 만든다. 범위가 2주라 달력 대신 칩을 쓰고, 오늘 표시) → 시각 고르기 → 진행 시간(숫자 조절, 자정 전에 끝나는 길이까지).

**개설 단계**: 제목·소개 → 주제·희망 직군 → 일시 → 장소 → 정원·입장 기준 → 요약 카드와 "만들기". 만들면 상세로 간다.

**로그인**: 가운데 정렬. 서비스를 한 줄로 설명하고, 소셜 버튼을 전체 폭으로 쌓는다. 소셜 버튼은 각 공급자의 공식 가이드를 따른다 (5장). 약관 안내는 약관이 생기면 버튼 아래에 둔다 (10장).

## 7. 문구 규칙

- **해요체**를 쓴다. 문장은 짧게, 존대하되 사과하지 않는다.
- 버튼은 무엇이 일어나는지 동사로 쓴다: 참여하기, 대기하기, 참여 취소, 만들기. 같은 행동은 흐름 내내 같은 이름을 쓰고 결과 토스트도 같은 말로 이어 간다("참여했어요").
- 오류는 무엇이 잘못됐고 어떻게 고치는지를 말한다. 서버 오류 코드(API 1장)마다 사용자 문구를 한 줄로 정한다. 시스템 용어를 노출하지 않는다.
- 빈 화면은 분위기가 아니라 다음 행동을 안내한다 (예: "아직 참여한 스터디가 없어요 / 스터디 찾아보기").
- 날짜·시각은 한국 시간 기준으로, "내일 오전 10:00"처럼 상대 표현과 절대 시각을 함께 쓴다.

## 8. 템플릿처럼 보이지 않기 점검 목록

화면 PR마다 확인한다.

- [ ] 한 화면에 `primary` 채움 버튼이 둘 이상이 아니다
- [ ] 모든 요소가 같은 모서리 값·같은 그림자가 아니다 (4장 위계를 따른다)
- [ ] 라이브러리 기본 스타일이 그대로 남은 곳이 없다 (색·모서리·간격이 토큰 값이다)
- [ ] 그라데이션, 글로우, 과한 그림자가 없다
- [ ] 의미 없는 아이콘 장식이 없다. 모든 아이콘에 글이 함께 있거나 `aria-label`이 있다
- [ ] 제목 한 단어만 색이나 기울임으로 강조하지 않았다
- [ ] 라벨을 전부 대문자·자간 확대로 쓰지 않았다
- [ ] 진입 애니메이션과 카드 호버 효과가 없다
- [ ] 상태가 색만으로 구분되지 않는다
- [ ] 360px에서 가로 스크롤이 없고 터치 대상이 44px 이상이다
- [ ] 빈 화면과 오류 문구를 직접 썼고, 행동을 안내한다

## 9. 변경 규칙

- 토큰 값을 바꾸면 이 문서를 먼저 고치고 `version`을 올린 뒤, 코드의 CSS 변수(`frontend/src/styles/tokens.css`)를 같은 PR에서 맞춘다.
- 새 컴포넌트를 만들면 5장에 규칙을 한 줄 추가한다. 규칙이 없는 컴포넌트는 만들지 않는다.
- 스타일은 CSS 변수와 CSS Modules로 쓴다. Tailwind 같은 도구를 따로 들이지 않는다.

### 확인 방법

- `npm test`의 `tokens.test.ts`가 이 문서 4장의 색·글자 표를 읽어 `tokens.css`와 값이 같은지, 4장의 글자·배경 조합이 WCAG AA(4.5:1) 이상인지 계산한다. 문서와 코드가 어긋나면 테스트가 실패한다.
- 공통 컴포넌트(좌석 줄, 출석 기록 줄, 버튼)는 옆의 테스트가 화면 낭독기 문구와 상태를 확인한다.
- 개발 서버의 `/design` 화면에서 토큰과 컴포넌트, 목록 카드와 상세 요약 시안을 한 번에 본다. 운영 빌드에서는 열리지 않는다. 브라우저 기기 에뮬레이션 360px 폭으로 8장 점검 목록을 확인한다.
